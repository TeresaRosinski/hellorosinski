Planning an ad that recommends products after someone answers a question or two? Use this tool to agree on what each person should see—and give your team the details to build and check it.

This portfolio demo recreates a planning tool I came up with, planned, and built using AI. The original runs on Epsilon’s internal servers.

New to decision-tree ads? Start here.

A treatment is a version of an ad. A decision tree connects a person’s answers to a set of product results. This planner turns that idea into a shared checklist, so the creative team, developer, and testers expect the same thing.

  1. Describe the experienceChoose the questions, products, and parts of each product that change.
  2. Check every answer pathSee exactly which content and destination slots each result needs.
  3. Share the planCopy the summary for your team and the setup files for your developer.

This tool plans the ad. Your team still builds it, supplies the final product content, and adds destination links.

Each product could have an image, name, and price. These are its elements. A variable is one named content entry, such as the image for product 1 in result A/B: cat_img_a_b_1.

A clickout is a numbered destination slot. Product 1’s image, name, and price all use the same clickout. The actual destination URL is added by your team.

If both questions have 2 answers, there are 4 answer combinations. With 3 products and 3 elements per product, that means 12 product slots and 36 content variables.

Planning rule: each answer combination gets its own product slots. If the same product appears in several results, it still needs a content entry in each result.

How the original worked: the Epsilon tool cycled through a list of test images hosted on Epsilon’s servers and assigned one to every image variable in the developer configuration. A developer could paste the configuration in and see images appear right away, instead of adding an image URL to each variable by hand. This portfolio demo mimics that automatic mapping with public, labeled placeholder images. Text variables use recognizable test values.

All outputs use the same result mapping.
